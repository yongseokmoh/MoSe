> **작성일:** 2026-09-27  
> **배경:** 기존 1단계 구조(AI 프롬프트가 수집·분류·판단·출력 전부 처리)에서 발생한 10대 논리 모순을 해소하기 위해 3-Layer 구조로 전면 재설계.

## 0. 현황 파악 (적용 전 기준)

- **종목 수:** 주요(major) 45개 + 관심(interest) 27개 = 총 72종목
- **1회 실행 시간:** 약 8~10분
- **1회 토큰 소모:** 약 597,000 토큰 (≈ 330원/회)
- **스케줄:** 매일 06:23 KST (UTC 21:23) GitHub Actions
- **AI 엔진:** DeepSeek API (`deepseek-reasoner` 거시 1회, `deepseek-chat` 나머지)

## 1. 핵심 설계 철학: 3-Layer 판단 구조

기존의 단일 AI 처리 구조를 책임 분리(SoC)에 따라 3개 레이어로 완전히 분리한다.

```
[Layer 1: 통계 엔진]  →  [Layer 2: AI 게이트키퍼]  →  [Layer 3: 출력 렌더러]
   (수학적 측정)            (문맥 검증)                 (사용자 노출)
```

### 2-2. 롤링 윈도우 관리 (매일 배치 시작 시 하우스키핑)

| 저장소 | 보존 기간 | 삭제 기준 |
|---|---|---|
| `baseline.entries` | **90일 (3개월)** | date가 오늘 기준 91일 이상이면 자동 삭제 |
| `output_pool.entries` | **30일 (1개월)** | date가 오늘 기준 31일 이상이면 자동 삭제 |

### 2-3. Git 저장 전략
- `news_cache.json`을 매일 배치 마지막 단계에서 `latest_report.json`과 함께 commit & push한다.
- 뉴스 **본문(description)은 `output_pool`에만** 저장하고, `baseline`에는 **날짜 + 키워드 배열만** 저장하여 경량화한다.
- 예상 파일 크기: baseline ≈ 800KB~1.5MB, output_pool ≈ 2~3MB (GitHub 용량 무관)

## 3. Layer 1: 통계 엔진 — 4차원 점수화

### 3-1. 최신성 점수 (Recency Score, 최대 40점)

| 경과 시간 | 점수 |
|---|---|
| 0 ~ 24시간 이내 | **40점** |
| 1일 초과 ~ 3일 이내 | **20점** |
| 3일 초과 ~ 7일 이내 | **10점** |
| 7일 초과 | **0점** (output_pool 잔류하되 노출 순위 후퇴) |

### 3-2. 매체 신뢰도 점수 (Publisher Score, 최대 20점)

| 등급 | 해당 매체 | 점수 |
|---|---|---|
| 1군 | 한국경제, 매일경제, 연합뉴스, 더벨, 인베스트조선, 블로터, 넘버스 | **20점** |
| 2군 | 뉴스1, 뉴시스, 전자신문, 연합인포맥스 | **12점** |
| 3군 | 머니투데이, 이데일리 | **8점** |
| 기타 | 나머지 | **0점** |

### 3-3. 집중 보도 점수 (Cluster Score, 최대 30점)

> 척도: **output_pool(1개월)** 내에서 이 기사와 핵심 키워드가 2개 이상 겹치는 기사 수(N)

| N (유사 기사 수) | 점수 |
|---|---|
| N >= 10 | **30점** |
| N >= 5 | **20점** |
| N >= 3 | **10점** |
| N < 3 | **0점** |

### 3-4. 이상 탐지 점수 (Anomaly Score, 최대 50점)

> 척도: **baseline(3개월)** 대비 최근 3일 폭증률 (Z-Score 방식)
> 절대 수량 비교 금지 — 대형주/소형주 공평 처리, 분기 주기 착시 방지

```
D_recent  = 이 기사 핵심 키워드의 최근 3일간 baseline 등장 빈도
D_baseline = 동일 키워드의 (3개월 전체 - 최근 3일)의 일평균 빈도

폭증률 = D_recent / (D_baseline + 0.5)   ← 0 나누기 방지 (Laplace smoothing)
```

| 폭증률 | 점수 | 의미 |
|---|---|---|
| >= 5.0배 | **50점** | 진짜 급등 (신규 대형 모멘텀) |
| >= 3.0배 | **30점** | 유의미한 증가 |
| >= 1.5배 | **10점** | 경미한 증가 |
| < 1.5배 | **0점** | 평범한 일상 뉴스 |

**예시: 상대적 비율의 효과**

| 종목 | 일평균 기사 | 오늘 기사 | 폭증률 | 결과 |
|---|---|---|---|---|
| 삼성전자 (대형) | 50건 | 80건 | 1.6배 → 10점 | 평범한 증가로 정확히 평가 |
| 클로봇 (소형) | 0.3건 | 4건 | 13.3배 → 50점 | 소형주 모멘텀 정확히 탐지 |

### 3-5. 시간 감쇠 계수 (Decay Factor)

```
감쇠 계수 = 0.85 ^ (기사 발행 후 경과 일수)

경과 0일: 1.00   경과 3일: 0.61   경과 5일: 0.44   경과 7일: 0.32

최종 점수 = (Recency + Publisher + Cluster + Anomaly) × DecayFactor
```

### 3-6. 콜드스타트 보호 (신규 등록 종목)

```javascript
// 등록 후 14일 미만이면 warmupComplete = false
// → Anomaly Score 강제 0점 (baseline 없으므로 이상 탐지 불가 상태)
// → 대신 Recency Score + Publisher Score 가중치 1.5배 부여
if (!stock.stockProfile.warmupComplete) {
  anomalyScore = 0;
  recencyScore *= 1.5;
  publisherScore *= 1.5;
}
// 14일 경과 시 warmupComplete = true로 자동 전환
```

## 4. Layer 2: AI 게이트키퍼

### 4-1. 입력 압축
- Layer 1 점수 기준 상위 **15개 후보군만** AI에게 전달 (기존 50개 → 15개로 70% 압축)

### 4-2. 홍보 복제 기사 탈락 규칙 (프롬프트 내 신규 추가)
```
다음 유형은 '홍보 복제 기사'로 분류하여 즉시 탈락시켜라:
  ① 여러 매체가 동일 내용을 베낀 기업 보도자료 기반 단순 MOU/협약 기사
  ② 실적 수치 없이 "전년 대비 성장", "사상 최대" 등 미사여구만 있는 홍보성 기사
  ③ 주가 등락 수치만 단순 나열하는 시황 기사

반드시 '주가 펀더멘털에 직접 영향을 주는 사건
(계약, 실적, 지배구조 변화, 규제, 신사업 진출)'위주로만 최종 5개를 선별하라.
```

### 4-3. 2-Track 쿼리 수집 (확증 편향 루프 해소)
```javascript
// 기존 (단일, 호재 편향)
`${stock.name} (특징주 OR 실적 OR 뉴스 OR 공시 OR 리포트 OR 신제품 OR 계약 OR 경영)`

// 변경 (2-Track 병렬)
const query_main = `${stock.name} (실적 OR 계약 OR 신사업 OR 투자 OR 인수 OR 신제품)`
const query_risk = `${stock.name} (소송 OR 리스크 OR 조사 OR 지배구조 OR 매각 OR 분쟁)`
// 두 결과를 합쳐 캐시에 병합 (중복은 id 해시로 자동 제거)
```

## 5. Layer 3: 출력 렌더러 — 뱃지 결정 규칙

| 조건 | 뱃지 | 의미 |
|---|---|---|
| `anomalyScore >= 30` | 🔴 **급등** | baseline 대비 폭증. 진짜 신규 모멘텀 |
| `clusterScore >= 20` AND `anomalyScore < 30` | 🔵 **주목** | 현재 집중 보도 중이나 신규 모멘텀은 아님 |
| 나머지 | 회색 **(일반)** | 참고용 |

> **'급등'과 '주목'의 척도 분리 (자기잠식 해소):**
> - Cluster는 output_pool(1개월) 기준
> - Anomaly는 baseline(3개월) 기준
> → 수학적으로 독립된 척도이므로 동시에 참일 수 있으며, 각각의 의미가 명확히 분리됨

## 6. 미국 섹터 분석: GICS 11대 섹터 적용

### 변경 전 (기존)
- 사용자의 한국 주요 종목으로부터 AI가 자유롭게 섹터명을 생성 → 한국식 테마명 혼재, 중복 매핑, 순환 논리

### 변경 후 (신규)
- 반드시 GICS 11대 섹터명 목록에서만 선택:
  `정보기술 | 임의소비재 | 산업재 | 커뮤니케이션 서비스 | 헬스케어 | 소재 | 금융 | 에너지 | 유틸리티 | 필수소비재 | 부동산`
- 섹터 선정 로직: "간밤 미국장에서 가장 유의미한 움직임이 있었던 GICS 섹터 3개를 선정하고, 그것이 나의 주요 종목([45개 목록])에 미치는 영향을 분석하라" (Top-down 방식)
- `historicalImpact` 필드의 목적 변경: 과거 패턴 → **"미국 섹터 흐름이 사용자의 한국 주요 종목에 미치는 영향"**으로 개인화

## 7. 배치 파이프라인 순서 (변경 후)

```
1. 캐시 하우스키핑 (91일+ baseline, 31일+ output_pool 삭제)
2. 2-Track 구글 뉴스 수집 (메인 + 리스크 쿼리 병렬)
3. 중복 체크 (링크 SHA256 해시 기준)
4. 신규 기사: 키워드 추출 → 4차원 점수화 → 캐시 저장
5. output_pool에서 최종 점수 상위 15개 추출
6. AI 게이트키퍼에게 전달 → 홍보 기사 탈락 → 최종 5개 선별 + 요약
7. Layer 3 뱃지 부여 (Anomaly/Cluster 점수 기준 결정)
8. latest_report.json 생성
9. news_cache.json + latest_report.json 동시 git commit & push
```

## 9. 해소된 논리 모순 10개 대조표

| 모순 | 내용 | 해소 방법 |
|---|---|---|
| 1 | GitHub 휘발성 환경 캐시 소실 | news_cache.json 매일 Git commit & push |
| 2 | 대형주 vs 소형주 절대 수량 딜레마 | Z-Score 상대적 폭증률 |
| 3 | 콜드스타트 신규 종목 오탐 | warmupComplete 14일 보호 플래그 |
| 4 | 과거 급등 기사 UI 박제 | Decay Factor 0.85^n |
| 5 | 금융 상투어 빈도 폭증 노이즈 | 불용어 사전 + AI 게이트키퍼 2중 차단 |
| 6 | 홍보 복제 기사 오탐 | AI 게이트키퍼 3가지 탈락 기준 |
| 7 | 주목/급등 수학적 자기잠식 | Cluster(1개월 풀) vs Anomaly(3개월 baseline) 분리 |
| 8 | 데일리 리포트 과거 기사 박제 | Decay Factor + 7일 초과 Recency 0점 |
| 9 | 분기 주기 baseline 오염 | Z-Score 비율 기반이므로 자동 면역 |
| 10 | 쿼리 확증 편향 루프 | 메인 + 리스크 2-Track 병렬 수집 |
